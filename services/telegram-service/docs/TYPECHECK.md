# Typecheck toolchain

Two checkers are installed. They do not agree on one committed file.

| Checker                                | Command              | Status                              |
| -------------------------------------- | -------------------- | ----------------------------------- |
| `tsc` (TypeScript 7.0.2)               | `bun run typecheck`  | **the gate** — must stay 0          |
| `tsrs` (oxc-project Rust port, 0.18.0) | `bunx tsrs --noEmit` | fast check; see the known gap below |

## Why two

`tsrs` is the Rust port of the TypeScript 7 compiler (oxc-project). Same
conformance target, much lower memory and faster. It is a devDependency so
the fast check does not depend on a `bunx` fetch at run time.

## Known gap: `proto/telegram_service.ts`

`tsrs` reports 2 errors at `proto/telegram_service.ts:3137` (TS2344 +
TS2536) in the `Exact<P, I extends P>` mapped type that
`protoc-gen-ts_proto` v2.11.2 emits. `tsc` reports 0 on the same file,
including with `--skipLibCheck false` (which only adds unrelated
`@types/node`-missing noise from `@grpc/proto-loader` and `grammy`).

The file is generated — `// Code generated by protoc-gen-ts_proto. DO NOT EDIT.`
— and is committed. So the difference is a tsrs conformance gap in a
distributed-conditional mapped type, not a defect in this repo's source.

**Until upstream fixes it: `tsc` is the gate. Do not treat tsrs errors in
`proto/telegram_service.ts` as regressions, and do not "fix" the generated
file by hand.** Re-run `bun run typecheck` to confirm the tree is clean.
